# 형제의 대장간 V0.2.5c

V0.2.5a를 기준으로 한 **공간 문법·충돌·레이어·동선 긴급 핫픽스**입니다.
이번 버전은 콘텐츠를 늘리는 대신 1층/2층을 실제로 걸어 다닐 수 있고, 오브젝트의 앞뒤가 자연스럽고, 상호작용이 서로 빼앗지 않는 공간으로 다시 정리했습니다.

핵심 원칙은 다음과 같습니다.

- 벽 부착형 / 바닥 고정형 / 가구 상단 소품 / 바닥 소형 소품을 분리
- 캐릭터와 가구의 depth는 스프라이트 중심이 아니라 **발 위치와 footprint의 bottom(baseY)** 으로 계산
- collision footprint와 interaction point를 별도 데이터로 관리
- 주요 통로를 먼저 확보한 뒤 가구를 배치
- 작은 소품의 영구 라벨을 줄이고 실제 위치 근처의 E 프롬프트를 우선

## 실행

### Windows
1. ZIP을 완전히 압축 풉니다.
2. `RUN_GAME.bat`을 더블클릭합니다.
3. 브라우저가 자동으로 `http://localhost:5173`을 엽니다.

Node.js가 설치되어 있어야 합니다.

```bash
npm run dev
```

## V0.2.5c 공간 문법 변경

### 1층 오브젝트 분류
`GameData.js`에 `OBJECT_CLASS`를 두고 오브젝트를 벽/바닥 고정/탁상/바닥 소품 문법으로 나눴습니다.
벽 도구와 선반은 창문과 같은 벽 높이 문법을 사용하고, 화로·모루·담금질통·작업대·숫돌·카운터·창고는 footprint를 가진 바닥 오브젝트로 취급합니다.

### 발 위치 기반 Depth Sorting
1층과 2층 모두 캐릭터의 `y`를 발 위치로 사용합니다.
큰 가구는 충돌 footprint의 아래쪽 `baseY`를 depth 값으로 사용합니다.
따라서 캐릭터가 모루/화로/침대/테이블보다 아래쪽에 서면 앞에 보이고, 위쪽 통로를 지나면 가구 뒤로 자연스럽게 들어갑니다.

ㄱ자 카운터는 상단 판과 세로 다리를 별도 drawable로 나눠 각각 다른 baseY를 가집니다.

### Collision과 Interaction 분리
`SHOP_COLLIDERS` / `LOFT_COLLIDERS`는 실제 바닥 점유 면적만 담당하고,
`INTERACTIONS` / `LOFT_INTERACTIONS`는 실제 사람이 서서 사용할 수 있는 별도 좌표와 반경을 담당합니다.

그 결과:
- 숫돌 자체는 통과 불가
- 숫돌 옆에서만 E 사용
- 카운터 판자는 통과 불가
- 직원측 접근 지점에서 카운터 사용
- 빗자루는 실제 좌하단 빗자루 근처에서만 집기 가능
- 숫돌/카운터 중앙에서 빗자루 E가 우선 뜨지 않음

### 1층 재배치
북쪽 작업 벽:
- 장작/석탄
- 화로
- 모루
- 담금질통

을 하나의 연속된 열 작업 라인으로 붙였습니다.
벽면 도구는 더 위로 올렸습니다.

중앙에는 큰 작업대와 숫돌을 두되 숫돌과 판매 카운터 사이에 실제 통로가 남도록 분리했습니다.
재료 창고는 좌하단 바닥 구석으로 내려 무거운 보관물처럼 보이게 했습니다.

우하단 판매 구역은:
- ㄱ자 카운터
- 직원용 접근 틈
- 문
- 작은 영업 표지판

을 서로 겹치지 않게 분리했습니다.

### 상인과 손님 동선
손님은 우측 문에서 들어와 CUSTOMER_ZONE 안의 카운터 앞/진열 공간으로 이동합니다.
일반 손님이 작업 구역으로 들어가지 않도록 유지합니다.

상인은 문 바깥에서 시작해 문 안으로 걸어 들어온 후 판매 구역의 대기 위치로 이동합니다.
문/표지판/카운터가 한 점에 겹쳐 막히지 않도록 위치를 분리했습니다.

### 측면 계단
1층 계단은 좌측 벽에 붙은 측면 목조 계단 문법을 유지했습니다.
계단 뒤 어두운 공간과 기둥을 사용해 건물 구조 일부처럼 보이게 했습니다.
층 이동 도착 위치와 상호작용 위치는 분리되어 있고 0.35초 재진입 쿨다운이 유지됩니다.

### 2층 생활공간
침대 두 개를 중앙 횡배치하는 숙소 문법을 버렸습니다.

- 형: 좌측 벽 세로 침대 + 낡은 궤짝 + 장화/컵/거칠게 둔 공구
- 동생: 우측 벽 세로 침대 + 작은 상자 + 책/정돈된 생활 소품
- 창문 아래: 두 사람이 함께 쓰는 공용 테이블
- 중앙: 작은 러그와 이동 공간
- 상단 한쪽: 수납장 + 작업복 흔적
- 우하단: 1층 구조와 연결되는 계단 랜딩

2층도 별도 `loftWorld`를 사용하며 침대, 공용 테이블, 개인 궤짝, 계단 footprint를 통과할 수 없습니다.

### 라벨 정책
작은 소품 및 통로를 복잡하게 만드는 라벨은 상시 표시하지 않습니다.
빗자루, 문, 작은 영업 표지판, 재료 창고, 판매 카운터는 근접 E 프롬프트로 확인할 수 있습니다.
화로/모루/담금질통/작업대/숫돌/판매 진열대/계단처럼 방향 파악에 중요한 오브젝트만 주요 라벨을 유지합니다.

### 이벤트 경고 마커
손님이 응대를 기다릴 때 작게 떠 있던 문자 `!` 대신 16px 픽셀 경고 플레이트를 렌더합니다.
노랑/주황 계열 판 + 짙은 외곽선 + 포인터로 멀리서도 이벤트 NPC임을 읽을 수 있게 했습니다.

### 작업 안내 / 하이라이트
기존 작업 추적 UI를 유지합니다.
현재 목표가 화로/모루/카운터/빗자루/계단/침대일 때 해당 오브젝트만 금색 glow로 강조합니다.
1366px 계열처럼 외부 사이드 패널을 쓰기 어려운 환경에서는 캔버스 우측 상단 compact tracker로 작업 안내를 유지합니다.

## 저장 호환성

`saveVersion: 4`를 유지합니다.
이번 패치는 맵 좌표/충돌/렌더/상호작용 규칙 중심이므로 기존 V4 세이브 데이터 구조를 바꾸지 않습니다.
V0.2.4 saveVersion 3 → V4 migration도 유지합니다.

저장된 플레이어 위치가 새 충돌 영역 안에 들어가는 경우 로드시 각 층의 `nearestWalkable()`을 사용해 안전한 바닥 위치로 보정합니다.
