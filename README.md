# 형제의 대장간 V0.2.5f.1

V0.2.5f.1는 새 콘텐츠 확장보다 기존 기능끼리 서로 방해하던 문제를 정리한 **상호작용 및 UX 안정화 핫픽스**입니다.

핵심 목표는 단순합니다.

> 보이는 대상을 누르는 게임에서, 플레이어가 의도한 대상을 정확히 사용하는 게임으로.

## 실행

### Windows
1. 전체 프로젝트 ZIP을 완전히 압축 풉니다.
2. `RUN_GAME.bat`을 더블클릭합니다.
3. 브라우저에서 `http://localhost:5173`이 열립니다.

Node.js가 설치되어 있어야 합니다.

### 개발 서버
```bash
npm install
npm run dev
```

### 테스트
```bash
npm test
```

### Production build
```bash
npm run build
```

정적 호스팅용 결과는 `dist/`에 생성됩니다.

Render Static Site 기준:
- Build Command: `npm run build`
- Publish Directory: `dist`

## 조작

- WASD / 방향키: 이동
- E / Enter: 현재 우선 상호작용
- Q: 조작 형제 변경
- I: 무기/재료 창고
- C: 달력 / 임대료
- ESC: Pause / 뒤로
- ↑ ↓ ← →: 메뉴 이동
- Enter / Space: 선택
- PageUp / PageDown: 창고 긴 목록 빠르게 이동
- 마우스 휠: 창고 목록 이동
- F3: 개발용 Interaction Resolver 디버그 표시

## V0.2.5f.1 주요 변경

### 1. 중앙 Interaction Resolver
E 입력 대상을 거리만으로 고르지 않습니다. 주변 후보의 `type`, `priority`, `distance`, `context`, `enabled`, `interactionPoint`를 중앙 Resolver가 비교합니다.

기본 방향은 다음과 같습니다.
- 현재 직접 제작 공정의 작업대가 최우선
- 빗자루 장착 중 처리 가능한 진상/먼지가 그 다음
- 창고, 판매대, 카운터, 문 등 주요 시설
- 중요 이벤트 NPC
- 일반 NPC와 형제 업무 지시
- 일반 소품

우선순위가 정말 비슷한 대상 둘 이상이 겹칠 때만 작은 선택 UI가 나타납니다.

### 2. PLAYER / ASSIST 위치 분리
주요 작업대의 플레이어 사용 위치와 형제 보조 위치를 분리했습니다.

`PLAYER_INTERACTION_POINTS`
- 플레이어가 실제 공정을 진행하는 자리

`ASSIST_POINTS`
- 형/동생이 보조 역할을 수행하는 자리

숫돌, 화로, 모루, 담금질통, 큰 작업대에서 보조 NPC가 플레이어 정면을 차지하지 않도록 했습니다. 직접 제작 단계가 바뀌면 관련 보조 역할도 호환되는 ASSIST_POINT로 이동합니다.

### 3. 먼지 / 빗자루 우선순위
빗자루를 들고 있지 않을 때 먼지는 E 상호작용 후보가 아닙니다.

따라서 빗자루 옆에 먼지가 있어도 `E 빗자루 줍기`가 정상적으로 우선합니다. 빗자루를 장착한 뒤에만 근거리 먼지가 `E 청소` 후보가 됩니다. 먼지 상호작용 반경도 작은 범위로 제한했습니다.

### 4. 자동 제작 후 창고 앞 비우기
형제 자동 제작은 다음 흐름으로 진행됩니다.

작업대 → 완성 → STORAGE_DELIVERY_POINT → 창고 저장 → PARKING_POINT 이동 → 대기

완성품을 전달한 뒤 창고 앞에서 계속 서 있지 않습니다. 창고 주변 플레이어 사용 위치와 NPC 전달/대기 위치도 분리했습니다.

### 5. 창고 다방향 접근
창고는 정면 한 점에만 의존하지 않습니다. 정면/좌측/우측 중 현재 플레이어와 가까운 안전한 상호작용 지점을 사용합니다.

창고 근처에 형제가 있어도 주요 시설인 창고가 기본 E 대상으로 우선합니다.

### 6. 창고 전체 완성품 리스트
창고 아이템 수와 진열 슬롯 수를 완전히 분리했습니다.

- 창고에는 완성품 1개, 7개, 20개, 30개 이상이 있어도 모두 접근 가능
- ↑/↓, PageUp/PageDown, 마우스 휠 지원
- 각 아이템의 품질, 특성, 제작자, 예상 가치 표시
- Enter로 첫 빈 진열 슬롯에 자동 배치
- 진열대는 6칸
- 6/6일 때는 창고 아이템을 삭제하지 않고 진열 불가 안내
- 진열품 회수 기능 유지

### 7. MessageManager / 알림 큐
기존 짧은 시스템 메시지는 중앙 MessageManager를 통해 관리합니다.

- 하단 Interaction Prompt: 최대 1개
- NPC 대화: 기존 대화창/말풍선
- System Notification: 화면 한쪽에 최대 3개 스택
- Important Event: 일반 알림보다 높은 우선순위
- Current Task: 기존 작업 추적 패널 유지
- 층 이동: 큰 중앙 메시지 대신 짧은 지역명 fade

중요 알림은 사소한 새 알림이 연속으로 발생해도 우선 표시 슬롯에서 밀려나지 않게 했습니다.

### 8. 문 Reservation / Entry Queue
상인, 일반 손님, 꼬마가 같은 문을 동시에 사용하지 않도록 공유 DoorReservationSystem을 사용합니다.

입장 시:
외부 대기점 → 문 예약 → 문 통과 → 실내 진입점 → 예약 해제

퇴장 시에도 같은 예약 시스템을 사용합니다. NPC를 물리 충돌로 막아 교착시키는 대신 짧은 대기점과 waypoint 예약으로 자연스럽게 순서를 정합니다.

### 9. Compound ㄱ자 카운터
카운터는 내부적으로 가로 collider와 세로 collider가 분리되어 있지만 둘 다 `counter_main`이라는 동일한 interaction group을 공유합니다.

현재 목표가 카운터이거나 카운터가 실제 선택 대상일 때 가로/세로 부분이 함께 금색 glow로 강조됩니다. 그래픽도 같은 상판/앞판/음영을 사용해 하나의 ㄱ자 시설처럼 읽히도록 유지했습니다.

### 10. 2층 개인 가구 보정
형과 동생의 개인 궤짝/상자를 벽에 붙은 평면 장식처럼 보이던 위치에서 실제 바닥 가구 영역으로 내렸습니다.

- 상판
- 앞면
- 측면
- 바닥 그림자
- 실제 collider / baseY depth

를 갖고, 침대와 시각적/이동 간격을 확보합니다. 기존 좌우 개인 영역, 공용 테이블, 러그, 창문, 수납장, 계단 구조는 유지합니다.

## 저장 호환성

`saveVersion: 5`입니다.

기존 V4 이하 저장은 자동 migration합니다.
- 기존 inventory는 그대로 유지
- 기존 5칸 display는 6칸으로 안전하게 확장
- 새 door reservation 데이터가 없어도 기본값 생성
- 형제 작업 데이터에 새 상태가 없으면 안전한 기본값 사용

문을 통과하는 찰나의 reservation은 로드 시 새로 구성합니다. 일반 랜덤 NPC의 정확한 픽셀 단위 문 점유 상태까지 복원해 교착을 만들기보다, 저장된 핵심 NPC/게임 상태를 기반으로 안전하게 이어가는 쪽을 우선합니다.

## 알려진 제한사항

V0.2.5f.1는 현재 대장간 프로토타입을 안정화하는 버전입니다. 마을 전체 맵, 광산/벌목 탐험, 직원 고용, 대규모 신규 무기/지역 등은 추가하지 않았습니다.

NPC 군중 처리는 복잡한 물리 충돌 시뮬레이션이 아니라 경로 + 문 reservation + 고정 assist/parking point 방식입니다. 이는 작은 대장간 안에서 교착을 줄이는 것을 우선한 의도된 구조입니다.
